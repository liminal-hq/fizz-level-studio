# Goals

The goals of Fizz Level Studio, ranked by what matters most when two of them pull against each other. The ids match `SPEC.md` §2. Each goal has a measure that a test, a script or a short manual check can settle.

When two goals conflict, the higher one wins. Trust comes before speed of editing: a studio that is fast but sometimes writes the wrong Rust is worse than none.

The ranks order goals, not targets. Of the two games, Fizz 2 is the more important target (`DECISIONS.md` D32), so the Fizz 2 goals below are the next to be worked on once the shared editor exists; within them, trust still comes first.

| Rank | Id | Goal | Measure of success |
| --- | --- | --- | --- |
| 1 | G-TRUST-1 | An exported script builds exactly the level the studio shows | For every level script in the repository, the exported function's `LevelData` equals the game's field by field and its `fingerprint()` matches. Today: 16 of 16 in `scripts/prove-all.sh`. Any new statement adds a proof case before it ships. |
| 2 | G-TRUST-3 | Nothing Claude writes reaches the file without the parser, and in propose mode nothing reaches it without the person | Tests: a malformed line rejects the whole call and stores nothing; in propose mode the level file is byte-identical after `edit_level`; no tool input field can set the mode. Today: covered in `packages/mcp/test/studio.test.ts`. |
| 3 | G-TRUST-2 | Hand-written lines are never rewritten | Test: after appending edits, and after rewriting owned object lines, every line the studio does not own is byte-identical to the original. Today: covered for appends (`edits.test.ts`, "hand-written lines are never rewritten" in `studio.test.ts`); not yet for object rewrites in the language package. |
| 4 | G-GAME-2 | Simulation rules come from the game's WebAssembly | Code review rule plus a test: the Paths lens and the playtest result for a fixture level equal what a Rust test of the same exports returns. No enemy-movement or physics rule is implemented in TypeScript outside `design/`. |
| 5 | G-GAME-1 | The studio's picture agrees with the game | `tools/verify-rasteriser.ts` reports every tile, item, spawn and the start agreeing for every level; `tools/verify-overworld.ts` reports 2,640 of 2,640 tiles, 27 of 27 points, the areas and the start. Today: all agree. |
| 6 | G-AI-2 | Propose is the default; the person alone switches mode, accepts and rejects | A fresh sidecar reads `mode: propose`; `tools/list` contains no accept, reject or mode tool; an unknown `mode` field in any tool input is rejected. Today: covered. |
| 7 | G-GAME-3 | Every name is checked against the game | A test fails when a tile, item, kind, level id, theme, area, scatter rate or sprite name in the language differs from the game's tables. Today: not built; `tables.ts` is copied by hand. |
| 8 | G-RUST-1 | Both authoring paths stay | All 16 Episode 1 levels open in the studio whether their source is a script or procedural Rust; a Rust-written level opens from data the game produces at run time. Today: offline only, through `dump_all_truth` and `tools/decompile-level.ts`. |
| 9 | G-FLOW-2 | Every change is one named undo step | Manual and Playwright checks: a paint stroke, a stamp, an object drag, a typed line and an accepted hunk each add exactly one History entry, and undo then redo leaves the script text identical. Today: prototype, partly covered by `e2e.cjs`, `obj-e2e.cjs` and `proto-crater-e2e.cjs`. |
| 10 | G-AI-1 | Claude can read, see the selection and propose every kind of change | Over MCP, Claude can propose a tile edit, an enemy, a lift move, a new overworld point and a changed unlock rule, each as a hunk the person can accept alone. Today: tiles and items only (`paint`, `clear`, `place`). |
| 11 | G-AI-3 | One script, shared | After the person types a line in the studio, the next `get_level` shows it; after an accept, the studio shows the line without a reload. Today: the server reloads the file on every call; the studio does not exist. |
| 12 | G-TRUST-4 | No unchecked claims | Every check result says which checks ran and which did not; a stubbed check returns "not run". Today: `run_checks` returns `playtest_bot: "not run"`; the prototype labels its canned ideas and stand-in bot. |
| 13 | G-RUST-2 | Procedural statements stay beside fills | The language keeps `terrain` runs, `crystal`, `pogo-cache`, `ladder`, stairs, `vine-nook`, `scatter` and `path`, and each has a proof case against a real level or a compile-and-run case. Today: terrain, `crystal`, `row`, `pogo-cache`, `scatter`, `path` are proven; the rest are compile-and-run only. |
| 14 | G-FLOW-1 | A visible change in under a minute | A person new to the studio opens Crater Fields and adds a ledge with a cheezie in under 60 seconds, unaided. Checked by a timed session. |
| 15 | G-FLOW-4 | Completion for the whole language | Typing the first letters of any word in `docs.ts` offers it; a test keeps `docs.ts` complete. Today: `docs.test.ts` keeps it complete; `compl-e2e.cjs` covers the prototype's completion. |
| 16 | G-FLOW-3 | A workspace the person arranges | Every window except the level drags, snaps within 8 px, resizes to its minimum, collapses, and returns with Ctrl+Shift+0; a saved layout survives a restart. Today: all but the restart, in the prototype. |
| 17 | G-PERF-1 | Paint within one frame | Measured in the studio: the 95th percentile from pointer event to updated canvas and script is under 16 ms on Marshmallow Meadows (220 × 32). Parse plus rasterise of a whole level is already under 1 ms in Bun on a desktop (0.35 ms for Frosting Spire). |
| 18 | G-PERF-2 | Open a level in under a second | Measured from choosing a starter level to the first drawn frame, for every Episode 1 level and the overworld. |
| 19 | G-PERF-3 | Proof in under two minutes | `time bash scripts/prove-all.sh` with a warm Cargo cache. Not timed yet. |
| 20 | G-F2-1 | The editor and the baker agree | A conformance corpus of Fizz 2 scripts with expected error codes, positions and printed output passes in the language package and in `fizz-script`; a script the editor accepts for Fizz 2 passes `fizz-bake check`. Today: not built. |
| 21 | G-F2-2 | A Fizz 1 export is never silent | Exporting a Fizz 2 level to Fizz 1 reports every E120, E121 and E122 error and every W104 snap, and the exported script has none of them. Today: not built. |
| 22 | G-F2-3 | Rules show as the game runs them | The dump view equals `fizz-bake dump` for the same script, record for record. Today: not built. |
| 23 | G-F2-4 | The target model holds as the games diverge | Every row of the capability matrix in `LANGUAGE.md` has a test in each profile, and a synthetic third profile loads with no editor code change. Today: not built. |
| 24 | G-F2-5 | Every Fizz 2 field a level holds can be authored | Each field of the `LEVL` header, object, rule and string records has a source form, a test that lowers it and an editor control. Today: designed in `LANGUAGE.md` and `EDITOR.md` section 13; not built. |
| 25 | G-F2-6 | The game's look is the game's | The Game view's frames equal the game's frame digests, and no Fizz 2 drawing rule is implemented in TypeScript. Today: not built. |
| 26 | G-SPR-1 | Sprites are shown truly and edited safely | Every object draws with its target's sprite; every sprite file round-trips byte for byte; generated sets cannot be edited. Today: not built. |
| 27 | G-EP3-1 | Later episodes need data, not code | An Episode 3 profile is added as data and passes the same corpus and matrix tests. Today: not built. |
| 28 | G-ST-1 | States and rules say every puzzle the owner described | A lock, a switch, an enemy-cleared door, a timer and a state-change chain each author, bake and run as fixtures, and every `lock` expands exactly. Today: not built. |
| 29 | G-BHV-1 | Behaviours are deterministic and within budget | Every behaviour fixture gives equal hashes on native, Web and DOS, and every handler's worst case is known at bake time. Today: not built. |
| 30 | G-WLD-1 | A world builds as one pack, from the studio | Build world produces the world pack through `fizz-bake` and its manifest matches. Today: not built. |
